# 监考插件兼容契约与验收清单

本契约用于监考实现一次性交付迁移。行为依据见 [行为基线](./proctor-migration-baseline.md)。状态：本次代码已实现；验收记录见 [部署与验证](./proctor-plugin-migration.md)。

## 对外兼容要求

| 项目 | 迁移约束 |
| --- | --- |
| 客户端 | 保持现有客户端源码及构建信任配置；不要求用户重新生成设备密钥 |
| 协议 | 保持 `hydro-proctor/1`、所有 action、证明方法、路径、规范化和签名算法 |
| URL | 保留 `/proctor/identity`、比赛监考接口、后台接口、主域及域前缀 |
| 响应 | 保留签名 payload 与 signature、明文 token 单次响应、completed/receipt、错误 params |
| 数据 | 保留集合、索引、状态、日志路径、密钥目录、keyId 和旧日志解密能力 |
| 权限 | Cookie 登录、sudo、系统权限、域/比赛权限及原有管理员例外继续生效 |
| 并发 | 一次性挑战、nonce 去重、令牌刷新、提交租约、上传/删除锁只有一套实现负责 |
| UI | 保留监考设置、日志分页与搜索、比赛开关、个人/团队日志状态、结束与补传入口 |

保持错误的具体原因可供客户端识别，例如版本不匹配与会话失效；不将 JSON 错误替换为 HTML 或登录重定向的成功响应。密钥查看仍是主动、sudo、no-store 的独立操作。

## 服务端接口边界

核心通过公共 API `registerContestSecurity` 注册唯一完整提供者。接口定义位于 `packages/hydrooj/src/lib/contest-security.ts`，插件实现位于 `packages/proctor/index.ts`。

| 方法 | 职责 | 失败处理 |
| --- | --- | --- |
| checkConfig | 启用监考前检查服务和密钥；核心保留开赛后策略锁定 | 抛出明确错误，原配置不应被当作保存成功 |
| requireAccess | 题目/比赛 GET 证明校验 | 不返回受保护内容 |
| requireRecordAccess | 记录读取证明；返回可再次校验的 access grant | 拒绝读取；只有提供者明确决定管理豁免时可返回 undefined |
| reserveSubmission | 证明校验并取得租约 | 不创建评测记录；成功取得后最终释放 |
| rankingFilter | 产生与原实现一致的有效成绩查询过滤器 | 缺少提供者时拒绝查询，禁止使用空过滤器放行 |
| teamStatus | 计算当前参赛成员的日志进度 | 不推断为全员上传完成 |

注册时校验完整性，重复注册拒绝。监考成绩过滤结果必须为非空对象，异常的 undefined、空过滤器或异步返回值不能被对象展开隐式转换成放行。注册由插件生命周期管理；旧清理回调不能清除后来的提供者。已建立的 access grant、提交租约检查同时绑定提供者实例，卸载/替换后拒绝继续使用；已取得租约仍允许执行清理释放。进行中的认证返回时也核对提供者实例，认证期间失效不继续读取；租约取得期间失效则释放后拒绝。

保留存储兼容字段与团队证据同步，不把密钥或具体会话对象传回核心。核心 WebSocket 持有的是 `ContestAccessGrant`，每次推送调用 assert。该接口继续叠加比赛截止、报名、代码可见与域权限检查。

## 插件缺失及故障约束

| 情况 | 必须发生的行为 |
| --- | --- |
| 普通非监考比赛且插件未启用 | 正常读取、提交、排名，不加载监考模型或管理页面 |
| 已启用监考，插件缺失或初始化失败 | 拒绝受保护读取、提交及有效成绩查询；明确提示管理员 |
| 前端插件未加载但后端启用 | 页面不能生成证明时由后端拒绝；不能凭网页标志放行 |
| 全局服务关闭、密钥缺失、版本不符 | 继续按原校验拒绝，不自动关闭比赛监考 |
| 监考模块异常 | 错误上抛，禁止 catch 后返回允许/空过滤器 |
| 无监考插件访问已有监考比赛的赛后排名 | 保持拒绝，避免缺少证据算法时把成绩恢复有效 |

赛后题目与记录复盘保留原权限；插件缺失不改变题库原本的公开性。管理页面入口随插件注册，插件恢复通过部署配置完成。本次不支持生产热卸载。

## 前端接口边界

ui-next 保留通用 `registerRequestSecurity`、`registerProtectedAccessResolver`、`protectedAccessHeaders` 与 `protectedSubmissionHeaders`。前端提供者负责实际原生桥接与保护路径匹配；必需的提交认证没有提供者时抛错，读取最终由服务端判定。路由、编辑器与错误页通过这些公共接口工作。

插件使用比赛编辑字段、参赛状态提示、参赛警告、结束文案和结束操作插槽；管理页通过 registerPage/registerManageEntry 注册。代码回放仅注册自身受保护 URL，并使用通用请求接口；赛事增强仅消费结束操作插槽。两者不导入监考插件私有实现。

公共 SDK 保留 `ProctorFinishButton`、`proctorAccessHeaders`、`registerProctorAccessResolver` 和 `ProctorAccessRequest` 的兼容别名，全部转发至通用插槽或注册接口，避免已有第三方插件因导出名称改变而失效。

前端证明只保存在请求头，不能放入 URL、localStorage、诊断日志或页面注入数据。网页结束按钮仅请求客户端确认，不宣称日志上传成功。

## 交付与回退

一次部署相同版本的所有后端 worker，并显式启用 `@hydrooj/proctor`；不同时运行旧核心认证与新插件认证。保留原镜像、配置、密钥和存储挂载。回退优先回退程序与插件配置，不覆盖升级后新写入的评测记录与日志。

不要在迁移发布中轮换密钥、修改版本策略或清理会话。保持现有安装包、密钥和数据可用，才能比较迁移前后的同一行为。
