# 荣誉头像框

## 使用方式

1. 系统管理首页 → 荣誉头像框管理（`/manage/honor-frames`）。
2. 上传素材、填写名称。新素材为未发布状态，只允许系统管理员预览。
3. 点击“发布”。查询获颁用户 ID，在素材卡片上点击“授予头像框”。重复授予不会产生重复记录。
4. 用户在个人设置 → 账户 → 荣誉头像框中选择佩戴，或取消佩戴。每页显示 12 个已获颁且已发布的头像框。
5. 管理员可重命名、停用素材，或撤销特定用户的获颁资格。管理素材每页 24 个，可按名称搜索。

素材要求：64–1024 像素正方形，透明 PNG/WebP，不超过 2 MiB。中心应透明以露出头像，边缘绘制装饰。
WebP 在浏览器中转换为静态 PNG；服务端独立解码、检查尺寸与透明度、重新编码，去除附加元数据。
不接收 SVG/HTML，不根据扩展名或客户端 MIME 类型判断文件安全性。透明度要求至少包含透明像素和可见像素。

## 全局数据与权限

- `honor.frame` 集合保存素材名称、发布状态、创建管理员和创建时间。
- 全局 `user` 文档中的 `honorFrameIds` 保存已获颁素材 ID，`honorFrameId` 保存佩戴 ID。不写入 `domain.user`。
- 管理接口要求 `PRIV_EDIT_SYSTEM`；域管理员和普通用户不能上传、发布、授予或撤销。
- 佩戴接口固定使用会话用户 ID，不能代替他人操作。写入过滤条件检查实际获颁资格，禁止客户端直接提供图片地址。
- 撤销资格与取消佩戴是同一次 MongoDB 原子更新；并发佩戴不能恢复已撤销资格。
- 停用保留用户获颁资格与佩戴选择，但不会返回有效装饰。重新发布后恢复；永久移除某用户的资格应使用“撤销”。
- 变更后清理跨域用户缓存，通过现有总线通知其他服务进程。已打开的页面需刷新或重新进入后获取管理员的最新变更，不额外建立实时推送连接。
- 上传、改名、发布/停用、授予、撤销写入系统操作日志。

无须升级 MongoDB 或手动迁移旧数据。无头像框字段的旧用户保持原样，新集合和索引随服务启动建立。
后端显式依赖纯 JavaScript `pngjs`，不引入原生图像库。

## 接口

以下接口即使使用 `/d/{domainId}` 前缀，也操作同一份全局头像框数据。

| 地址 | 用途 |
| --- | --- |
| `GET /manage/honor-frames?page=1&q=名称&uid=用户ID` | 素材列表及目标用户获颁状态 |
| `POST /manage/honor-frames`，`operation=upload` | 上传 `file` 和 `name`，创建草稿 |
| 同上，`operation=update` | 更新 `id` 对应的 `name`、`active` |
| 同上，`operation=grant/revoke` | 对 `uid` 授予/撤销 `id` |
| `GET /home/honor-frames?page=1` | 当前用户可用头像框、当前佩戴状态 |
| `POST /home/honor-frames` | 佩戴 `id`，空字符串表示取消佩戴 |
| `GET /honor-frame/{id}.png` | 图片；未发布素材仅系统管理员可读取 |

## 前端展示

公开用户对象与会话用户统一附带：

```ts
honorFrame: { id: string; name: string; imageUrl: string } | null;
```

`UserAvatar` / `FramedAvatar` 使用这个字段，不读取域设置。
列表的批量用户查询只批量解析一次素材，用户搜索显式投影也包含 `honorFrame`。
现有头像外围预留 2–10px；装饰层不捕获点击、键盘焦点或读屏，加载失败保留相同尺寸。
域头像继续使用原来的域头像规则，不佩戴用户头像框。

## 回归覆盖

- 服务端图片解码、透明度、CRC、体积与解压尺寸边界。
- 系统权限、未获颁佩戴拒绝、停用素材拒绝、重复授予、撤销/佩戴竞态。
- 跨域公开用户序列化、批量用户查询、全局缓存清理、分页上限。
- 上传失败的存储清理、草稿默认未发布。
- 前端管理入口权限、佩戴/取消、重复操作锁定、错误通知、卸载取消请求。
