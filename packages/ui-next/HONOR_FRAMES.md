# 荣誉头像框：前端预留与后续接入说明

本轮只提供前端展示基础和功能占位，不包含数据库、上传接口、颁发或佩戴接口。

## 已实现的界面

- `FramedAvatar` 包装原有 Mantine Avatar：头像尺寸不变，四周按头像尺寸预留 2–10px，装饰层覆盖整个预留区域。
- 空状态、图片加载中、加载失败均保留相同尺寸，不会导致列表重新排布。装饰层不接受鼠标事件、不参与读屏和键盘焦点。
- `UserAvatar` 读取用户的 `honorFrame`，不读取域设置，也不按域缓存头像框。
- 用户头像已统一接入顶部个人入口、个人主页、排行榜、题解、题目上传者、训练报名用户、比赛用户、域用户和消息页。搜索选项同样预留装饰空间。
- 个人设置 → 账户：预留“荣誉头像框”卡片、当前佩戴预览和禁用的选择按钮。
- 系统管理首页：仅系统管理员可见素材本地预览和禁用的发布按钮。选择 PNG/WebP 后仅生成浏览器 Blob URL；不发请求、不持久化。换文件、关闭页面时释放 URL。
- 域头像与用户头像是两种资源：域切换、域列表、域搜索继续使用原有域头像，不佩戴用户头像框。

## 前端数据约定

未来服务端在公开用户资料和当前会话用户中附带同一个可选字段：

```ts
interface HonorFrame {
  id: string;
  name: string;
  imageUrl: string;
}

interface PublicUser {
  _id: number;
  // 其他用户字段保持不变
  honorFrame?: HonorFrame | null;
}
```

`undefined` / `null` 表示没有佩戴。URL 使用全站根路径或完整 HTTPS 地址，不使用依赖当前域的相对路径。Blob URL 仅用于本地素材预览。

前端不能凭空保证服务端返回的资料在各域一致；后续必须在全局用户模型中存储佩戴状态，并由所有资料接口统一序列化。不要把字段写到 domain-user、域配置或以 domainId 为键的 localStorage 中。

## 后续后端实现

1. 建立全局头像框素材库，记录名称、资源地址、发布状态、创建管理员及时间。
2. 全局用户保存已获颁的头像框 ID 与当前佩戴 ID；域内排名、昵称仍使用原有域数据，头像框始终从全局用户读取。
3. 上传、发布、颁发、撤销必须在服务端检查系统管理员权限（当前 UI 采用 `PRIV_EDIT_SYSTEM`），域管理员权限不能替代系统权限。
4. 用户佩戴接口只能选择其已获得且仍有效的头像框；不能接受客户端直接指定任意资源 URL。
5. 向 `UserContext`、用户详情、`udict`、排行榜、报名列表、用户搜索等公开用户序列化结果补充同一字段。搜索接口有显式字段投影时，同步更新前后端投影。
6. 上传端校验真实文件类型、文件大小、尺寸和解码结果。建议限制为方形透明 PNG/WebP，中心留空用于头像，边缘装饰包含在画布内；不直接接受未清洗 SVG 或 HTML。
7. 发布或撤销后刷新全局用户缓存和会话资料。使用版本化资源 URL，避免 CDN 缓存旧图；删除已佩戴素材时返回空状态。

上线前需要补充跨域一致性、上传鉴权、颁发/撤销、过期资源及缓存失效的接口测试。当前禁用按钮不代表这些后端能力已经实现。
